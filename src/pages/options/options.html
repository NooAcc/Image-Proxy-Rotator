请求统计

ⓘ这些数字怎么数出来的

只统计命中了你的规则的请求；其余请求本就该直连，不计入。

成功的判定是 HTTP 状态码小于 400。「平均耗时」只算真的测到耗时的那部分请求。

「对端确认是代理」看的是响应从哪个地址回来的 —— 落在你某个节点上，就是走通了代理的硬证据。

节点使用分布

ⓘ这张表为什么可能认不出节点

归因靠请求的对端 IP —— 走代理时对端就是代理本身。只有 IP，没有端口， 所以多个节点共用同一个地址（只有端口不同）时无法区分。

这类请求计入「无法归因」，不会硬塞给某个节点。节点写成域名时要先测速一次才认得出。

批量导入

ⓘ支持哪些格式

每行一个。http://主机:端口、http://用户名:密码@主机:端口， 或 主机:端口（按 HTTP 处理）。也可直接粘贴 base64 订阅内容。

行尾 #名称 用于命名，# 开头的行是注释。

SOCKS4 / SOCKS5 / VLESS / VMess / Hysteria2 / Trojan / Shadowsocks 不受支持，粘贴后会被逐条列出并忽略。

测速与健康检查

ⓘ测速地址该填什么

应当是一个返回极小响应且允许跨域的端点，例如只回 204 的探测地址。 下载一张大图当测速目标，量到的是带宽而不是延迟。

测速请求会被强制路由到被测节点，所以一次测速就等价于验证了这条节点的 CONNECT 通路。
